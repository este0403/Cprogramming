## 12장 포인터의 이해

### 실습과제 1

아래의 변수가 다음처럼 메모리에 할당될 때, 각 수식의 결과값과 자료형은 다음과 같다.

```c
char ch = 'A';
int in = 10;
double db = 3.4;
```

메모리 배치: ch(100), in(101~104), db(105~112)

| 수식 | 결과값 | 결과값의 자료형 |
|---|---|---|
| &ch | 100 | char* |
| &in | 101 | int* |
| &db | 105 | double* |
| \*&ch | 'A' | char |
| \*&in | 10 | int |
| \*&db | 3.4 | double |

**설명**
- `&` 연산자는 변수의 주소를 반환하므로, 결과값의 자료형은 항상 "원래타입*" 형태가 된다.
- `*&x`는 `*(&x)`로 계산된다(단항 연산자는 변수에 가까운 것부터, 즉 오른쪽에서 왼쪽으로 결합). `&x`로 주소를 구한 뒤 `*`로 그 주소가 가리키는 값을 다시 구하므로, 결국 원래 변수 x와 완전히 동일한 값과 자료형이 된다.

### 실습과제 3 요약

`(int*)125`처럼 정수 상수를 포인터로 강제형변환하는 이유와, 이런 포인터로 `*ptr = 10;`을 실행했을 때 실행이 중단되는 이유는 `실습과제_3.c` 파일의 주석에 자세히 설명되어 있다.

핵심 요약:
- 강제형변환은 정수 값을 포인터 타입에 맞춰 대입하기 위한 것일 뿐, 그 주소가 실제로 유효함을 보장하지 않는다.
- 125번지는 프로세스에 할당되지 않은(소유권 없는) 메모리 영역이므로, 그곳에 값을 쓰려고 하면 운영체제의 메모리 보호 기능에 의해 접근이 차단되어 세그멘테이션 오류로 프로그램이 강제 종료된다.
