## 실습과제1

### 1. 주소에 의한 호출(call by reference)을 사용해야 하는 3가지 경우

1. **다른 함수에서 선언된 지역 변수의 값을 변경하고 싶은 경우**
   값에 의한 호출은 인자를 매개변수로 복사해서 전달하므로, 함수 안에서 바꿔도 원본은 그대로이다. 원본 변수의 주소를 전달하면 `*포인터`로 원본을 직접 바꿀 수 있다. (예: `add(2, 3, &result)`에서 `*res = a + b;`)
2. **배열을 함수의 인자로 전달하는 경우**
   배열을 값으로 복사하면 메모리를 많이 쓰고 복사 시간이 오래 걸려 성능이 떨어진다. 그래서 C언어는 배열 인자를 주소로만 전달하도록 허용한다. 매개변수는 `int* pt` 또는 `int pt[]`로 선언하며, 컴파일러가 둘 다 포인터로 취급한다. 포인터 변수 크기(8바이트)만 할당되므로 메모리를 절약하고 속도도 빨라진다.
3. **함수의 반환값이 2개 이상인 경우**
   C언어 함수는 반환값을 1개만 가질 수 있다. 결과를 저장할 변수의 주소를 매개변수로 받아 그 주소에 값을 써 주면 여러 개의 결과를 돌려줄 수 있다. (예: `get_maxmin(grade, &max, &min)`) 결국 1번 경우와 같은 원리이다.

### 2. 최대값을 구하는 알고리즘

1. 첫 번째 원소를 최대값 변수 `max`에 저장한다. (`max = array[0]`)
2. 두 번째 원소부터 마지막 원소까지 차례로 `max`와 비교한다.
3. 현재 원소가 `max`보다 크면 `max`를 그 원소 값으로 바꾼다.
4. 모든 원소를 비교한 뒤 `max`에 남아 있는 값이 최대값이다.

n개의 원소를 (n-1)번 비교하면 되므로 배열을 한 번만 훑으면 된다. 최소값은 비교 방향(`<`)만 바꾸면 같은 방식으로 구할 수 있다.

### 3. const 선언을 사용하는 이유 (교재 322~323쪽)

`const`는 값이 바뀌면 안 되는 대상을 상수처럼 만들어 **실수로 값이 변경되는 것을 컴파일 단계에서 막아 준다.** 특히 포인터를 매개변수로 받는 함수에서 유용하다.

- 주소를 받으면 함수가 원본을 바꿀 수 있는데, 값을 읽기만 하는 함수(예: 배열 출력, 평균 계산)라면 `const int* ptr`로 선언해서 실수로 `*ptr = 30;` 같은 대입을 하면 컴파일 에러가 나도록 한다.
- 함수 사용자에게 "이 함수는 전달한 데이터를 바꾸지 않는다"는 약속을 명확히 보여 주므로 코드의 의도가 분명해지고 안전해진다.

`const`의 위치에 따른 차이는 다음과 같다.

| 선언 | 의미 | `*ptr = 값` | `ptr = &다른변수` |
|---|---|---|---|
| `const int* ptr` | 가리키는 변수 값을 못 바꿈 | 에러 | 가능 |
| `int* const ptr` | 포인터 변수(주소)를 못 바꿈 | 가능 | 에러 |
| `const int* const ptr` | 둘 다 못 바꿈 | 에러 | 에러 |

## 실습과제5 선택 문제

교재 324쪽 문제 14-2 중 **문제 2**를 풀었다. (`실습과제5.c`)

**문제 2 — 지적할 만한 사항**
`ShowData(const int* ptr)`는 값을 바꾸지 않겠다는 약속으로 `const`를 붙였는데, 함수 안에서 `int* rptr = ptr;`처럼 const가 없는 포인터에 주소를 넣고 `*rptr = 20;`으로 값을 바꾼다. 이렇게 하면 const가 무력화되어 main 함수의 `num`이 20으로 바뀐다. `rptr`도 `const int* rptr = ptr;`로 선언하면 `*rptr = 20;`이 컴파일 에러가 되어 값이 보호된다.

**참고: 문제 1 — `const int* arr`를 사용한 이유**
`ShowAllData`는 배열을 출력만 하고 바꾸지 않는 함수이다. 배열은 주소로 전달되므로 함수가 원본을 바꿀 수 있는데, `const`를 붙여 두면 실수로 원소를 바꾸는 코드를 컴파일러가 잡아 준다. 이 함수는 배열을 읽기만 한다는 정의한 사람의 의도를 나타내기도 한다.
