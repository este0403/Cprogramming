## 실습과제1

### 1. 함수 선언, 호출, 정의

| 구분 | 설명 | 예 |
|---|---|---|
| 선언 | 컴파일러에게 함수의 이름, 반환형, 매개변수 자료형을 미리 알려 줌. 호출 전에 해야 하며 본문은 없음 | `int sum(int a, int b);` |
| 호출 | 정의된 함수를 실행시킴. 인자를 전달하고 반환값을 받음 | `res = sum(10, 20);` |
| 정의 | 함수의 실제 동작(본문 `{ }`)을 작성함. 컴파일되어 코드영역에 저장됨 | `int sum(int a, int b) { return a + b; }` |

### 2. 함수의 자료형은?

반환형과 매개변수의 자료형으로 정의된다. 형식은 `반환형(매개변수자료형1, 매개변수자료형2, ...)`이다.

- `int sum(int a, int b)` → `int(int, int)`
- `double abs(double a)` → `double(double)`
- 함수 정의 내용이 달라도 반환형과 매개변수의 자료형·개수가 같으면 자료형은 같다. (`sum`과 `sub`는 모두 `int(int, int)`)

### 3. 함수명의 자료형은?

함수명은 함수가 저장된 메모리의 시작주소(상수)이므로 "함수의 자료형에 *를 붙인 것", 즉 함수 포인터 자료형이다. 형식은 `반환형 (*)(매개변수자료형1, 매개변수자료형2, ...)`이다.

- `sum`의 자료형 → `int (*)(int, int)`
- `abs`의 자료형 → `double (*)(double)`

함수 포인터 변수는 `반환형 (*변수명)(매개변수자료형, ...)`로 선언한다. 괄호가 없으면 반환형이 포인터인 함수의 선언이 되므로 주의한다.

```c
int (*fp)(int, int);   // 함수 포인터 fp 선언
int *fp(int, int);     // 반환형이 int*인 함수 fp 선언 (함수 포인터 아님)
```

### 4. void 포인터의 용도는?

`void*`는 가리키는 자료형이 정해져 있지 않은 포인터로, char/int/double 변수의 주소는 물론 함수의 주소까지 모든 종류의 주소를 하나의 포인터 변수에 저장할 수 있다. 자료형별로 포인터 변수를 따로 만들 필요가 없어지므로, 자료형에 상관없이 동작하는 범용 함수(예: 어떤 자료형이든 교환하는 swap, `memcpy` 같은 라이브러리 함수)의 매개변수로 주로 쓴다.

### 5. void 포인터에 간접참조 연산을 적용할 때 주의할 점은?

`void*`는 가리키는 자료형이 없어서 저장된 주소로부터 몇 바이트를 읽어야 하는지 알 수 없다. 따라서 `*vp`, `vp++`, `*vp = 20` 같은 연산은 오류이다. 반드시 **강제 형변환으로 가리키는 자료형을 정한 뒤** 사용해야 한다.

```c
int in = 10;
void* vp = &in;
printf("%d\n", *(int*)vp);   // 형변환 후 간접참조 가능
vp = (int*)vp + 1;           // 형변환 후 정수 덧셈 가능
*(int*)vp = 20;              // 형변환 후 값 저장 가능
```

### 6. 강제형변환과 자동형변환

| 구분 | 자동형변환(묵시적 형변환) | 강제형변환(명시적 형변환) |
|---|---|---|
| 의미 | 컴파일러가 알아서 자료형을 바꿈 | 프로그래머가 `(자료형)`을 붙여 직접 바꿈 |
| 발생 | 서로 다른 자료형 간 연산, 대입, 인자 전달 시 | 변환 코드를 직접 작성할 때 |
| 방향 | 보통 작은 자료형 → 큰 자료형 (`int` → `double`)으로 값 손실 없이 변환 | 큰 자료형 → 작은 자료형 등 자동으로 안 되는 변환도 가능 (값 손실 위험) |
| 예 | `double d = 10;` → `10.0`으로 저장 | `int n = (int)3.7;` → `3`으로 저장 |
| 포인터 예 | `void* vp = &in;` (포인터 → void*는 자동) | `*(int*)vp` (void* → int*는 강제) |

## 실습과제2 코드 설명

### 함수 포인터 매개변수 (`apply_and_print`)

`void apply_and_print(const int* arr, int n, int (*f)(int))`

- 세 번째 매개변수 `f`가 "int를 받아 int를 반환하는 함수"의 주소를 저장하는 함수 포인터이다.
- 반복문과 출력 같은 공통 코드는 한 곳에 두고, 바뀌는 연산(`square`, `twice`)은 호출할 때 함수명으로 전달한다.
- 함수 안에서 `f(arr[i])`로 호출하면 전달받은 함수가 실행된다. 새 연산이 필요하면 함수 하나만 추가하면 되므로 코드가 줄고 유지보수가 쉽다.

### void 포인터 매개변수 (`swap_any`)

`void swap_any(void* a, void* b, size_t size)`

- `void*`로 받으므로 `int`, `double` 등 어떤 변수의 주소도 전달할 수 있다.
- `void*`는 `*` 연산을 할 수 없으므로 `memcpy`로 `size` 바이트를 통째로 복사해 값을 교환한다. 자료형의 크기는 `sizeof`로 함께 넘긴다.
- `swap_any(&x, &y, sizeof(int))`와 `swap_any(&p, &q, sizeof(double))`처럼 함수 하나로 두 자료형을 모두 처리한다.

### 실행 결과

```
[함수 포인터 매개변수]
제곱 : 1 4 9 16 25 
두 배 : 2 4 6 8 10 

[void 포인터 매개변수]
교환 전 : x=10, y=20 / p=1.5, q=2.5
교환 후 : x=20, y=10 / p=2.5, q=1.5
```

### 도전과제1: 배열 회전

- 오른쪽으로 90° 회전하면 회전 전 `arr[i][j]`가 회전 후 `arr[j][N-1-i]` 위치로 이동한다. (맨 아래 행이 첫 번째 열이 됨)
- 같은 배열에 바로 덮어쓰면 값이 사라지므로 임시 배열 `tmp`에 결과를 만든 뒤 원래 배열로 복사한다.
- 초기 상태와 90°, 180°, 270° 회전 결과를 차례로 출력하며, 교재 그림 20-1과 같다.

### 도전과제2: 달팽이 배열

- `top`, `bottom`, `left`, `right`로 아직 채우지 않은 영역을 관리한다.
- 위쪽 행(왼쪽→오른쪽), 오른쪽 열(위→아래), 아래쪽 행(오른쪽→왼쪽), 왼쪽 열(아래→위) 순서로 한 바퀴를 돌며 값을 채우고, 한 바퀴가 끝날 때마다 영역을 한 칸씩 줄인다.
- n이 홀수일 때 가운데 한 칸이 남는 경우나 n이 1~2인 경우를 위해 3), 4)번 방향에서는 남은 행/열이 있는지 확인한다.

```
숫자를 입력하시오 : 5
   1   2   3   4   5
  16  17  18  19   6
  15  24  25  20   7
  14  23  22  21   8
  13  12  11  10   9
```

### 도전과제3: 0~99 난수

- `rand()`는 0 이상 `RAND_MAX` 이하의 난수를 반환하므로, `rand() % 100`으로 100으로 나눈 나머지(0~99)만 얻는다.
- `RAND_MAX`는 컴파일러마다 다르다. (Visual Studio는 32767, Linux gcc는 2147483647)
- 씨앗(seed)을 바꾸지 않았으므로 실행할 때마다 같은 난수가 나온다. 매번 다르게 하려면 `srand((unsigned)time(NULL))`을 추가한다.
