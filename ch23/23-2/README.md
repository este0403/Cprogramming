## 실습과제1

### 1. 구조체가 왜 필요한가?

학생 한 명의 정보(학번, 이름, 학점 등)처럼 **서로 관련 있는 데이터를 하나의 자료형으로 묶기 위해** 필요하다. 구조체가 없으면 `int number[7]; char name[7][10]; double grade[7];`처럼 변수를 따로따로 선언하고 함수에도 일일이 넘겨야 한다. 구조체 `struct student`를 정의하면 학생 1명 = 변수 1개가 되어 배열(`Student arr[7]`), 포인터(`Student* sptr`), 함수 인자·반환값으로 한 번에 다룰 수 있다. 데이터의 표현과 관리가 쉬워지고 생산성이 올라가므로, 대규모 코드 작성에서 필수적인 기능이다. 구조체 안에 구조체를 멤버로 두는 **중첩 구조체**(예: `Circle` 안의 `Point cen`)로 복잡한 데이터도 계층적으로 표현할 수 있다.

### 2. 공용체가 왜 필요한가?

구조체의 멤버는 각각 별도의 메모리 공간을 갖지만, 공용체(`union`)의 멤버는 **가장 큰 멤버 크기의 공간 하나를 모두 공유**한다. 따라서

- **하나의 메모리 공간을 2가지 이상의 방식으로 접근**할 수 있다. 예를 들어 4바이트 정수를 `int`로도, `char[4]`로도, 상위/하위 2바이트(`unsigned short` 2개)로도 읽을 수 있어 바이트 단위 분석(엔디안 확인 등)에 유용하다.
- 동시에 하나의 멤버만 의미 있게 쓰는 경우 **메모리를 절약**할 수 있다. (예: `sizeof(SBox)`는 16바이트, `sizeof(UBox)`는 8바이트)

단, 한 멤버에 값을 쓰면 다른 멤버의 값이 덮어써지므로(예제5에서 `mem3`에 7.15를 쓰면 `mem1`, `mem2`가 쓰레기 값이 됨) 한 번에 한 멤버만 사용해야 한다.

### 3. 열거형이 왜 필요한가?

기본 자료형은 값의 범위만 정해져 있을 뿐 그 값의 **의미**를 담지 못한다. 열거형(`enum`)은 변수가 가질 수 있는 값들을 `SUN, MON, ...`, `Do, Re, Mi, ...`처럼 **기호 상수(열거형 상수)로 묶어서 직접 정의**하는 자료형이다.

| 방식 | 문제점 / 장점 |
|---|---|
| 정수 사용 (`case 1:`) | 숫자가 무슨 뜻인지 외워야 한다. |
| `#define` 기호 상수 | 실수로 같은 값을 두 번 정의해도 컴파일러가 모른다. |
| **열거형** | 값을 안 적으면 0부터 1씩 자동 할당되어 **중복이 자동으로 방지**되고, 관련 상수가 한 자료형으로 묶여 **가독성이 높아진다.** |

변수 선언이 아니라 상수 선언이 목적이면 `enum { Do, Re, Mi };`처럼 열거형 이름을 생략하기도 한다.

## 실습과제3 참고 (리틀엔디안)

인텔 CPU는 **리틀엔디안**이라 상위 바이트가 높은 주소에 저장된다. 입력 `0x11223344`는 메모리에 다음과 같이 놓인다.

| 주소 | 낮음 → 높음 |||
|---|---|---|---|---|
| 배열 첨자 | `bBuf[0]` | `bBuf[1]` | `bBuf[2]` | `bBuf[3]` |
| 값 | 44 | 33 | 22 | 11 |
| 의미 | 최하위(1번째) | 2번째 | 3번째 | 최상위(4번째) |

바이트를 `%x`로 출력할 때 부호 확장으로 `ffffff…`가 붙지 않도록 `unsigned char`를 사용했다.
