## 실습과제4 — 20페이지 예제4-1의 실행 결과 설명

### 문제의 코드

```c
ret = fscanf(fp, "%s%c%d", name, &gender, &age);   // %c 앞에 공백이 없음
```

`friend.txt`에는 `홍길동 M 23`, `임꺽정 M 40`, `장길산 F 30`이 저장되어 있다. 예제4(`"%s %c %d"`)는 정상 동작하지만, 예제4-1은 서식 문자열에서 `%c` 앞뒤의 공백을 뺐기 때문에 결과가 엇갈린다.

### 핵심 원리

1. `%s`는 **공백·탭·줄바꿈 직전까지** 읽고, 구분 문자는 버퍼에 그대로 남긴다.
2. `%c`는 **구분 문자도 한 글자로 읽는다.** (`" %c"`처럼 앞에 공백이 있어야 구분 문자를 건너뛴다.)
3. `%d`는 앞의 공백류를 건너뛰고 숫자를 읽는다. 하지만 숫자가 아닌 문자(`M`, `F`)를 만나면 **읽기에 실패**하고, 그 문자는 버퍼에 남으며 `age`는 **값이 바뀌지 않는다.**
4. 반환값 `ret`는 정상적으로 저장한 항목 수이다. `%d`가 실패하면 2가 되지만 EOF(-1)가 아니므로 반복은 계속된다.
5. `age`는 초기화하지 않아 쓰레기값(`-858993460`, Visual Studio 디버그 모드의 초기값 `0xCCCCCCCC`)이 들어 있다.

### 반복별 추적

(`␣`는 공백, `\n`은 줄바꿈. 파일 내용: `홍길동␣M␣23\n임꺽정␣M␣40\n장길산␣F␣30`)

| 반복 | `%s` | `%c` | `%d` | 반환값 | 출력 |
|---|---|---|---|---|---|
| 1 | `홍길동` (`␣`에서 멈춤) | `␣` (공백을 문자로 읽음) | `M`은 숫자가 아니어서 **실패**, `age`는 쓰레기값 그대로 | 2 | `홍길동 ␣ -858993460` |
| 2 | `M` (남아 있던 `M`을 읽음) | `␣` | `23` (`\n`에서 멈춤) | 3 | `M ␣ 23` |
| 3 | `임꺽정` (앞의 `\n`은 `%s`가 건너뜀) | `␣` | `M`에서 **실패**, `age`는 이전 값 `23` 유지 | 2 | `임꺽정 ␣ 23` |
| 4 | `M` | `␣` | `40` | 3 | `M ␣ 40` |
| 5 | `장길산` | `␣` | `F`에서 **실패**, `age`는 이전 값 `40` 유지 | 2 | `장길산 ␣ 40` |
| 6 | `F` | `␣` | `30` (파일 끝에서 멈춤) | 3 | `F ␣ 30` |
| 7 | 파일 끝 → 입력 실패 | | | EOF(-1) | `break`로 종료 |

그래서 화면에는 이름 줄과 `M`/`F` 줄이 번갈아 출력되고, 성별 자리에는 공백이 들어가 있으며, 나이는 한 칸씩 밀려서 이전 사람의 값이 나온다.

```
홍길동 -858993460
M 23
임꺽정 23
M 40
장길산 40
F 30
```

### 해결 방법

`scanf`처럼 구분 문자를 제거하고 읽어야 한다. 서식 문자열에 공백을 넣어 `%c` 앞의 구분 문자를 건너뛰게 하면 예제4와 같이 정상 동작한다.

```c
ret = fscanf(fp, "%s %c %d", name, &gender, &age);
```

(`gcc`로 같은 데이터를 넣어 위 추적과 동일한 결과가 나오는 것을 확인했다.)
