# 24장 파일 입출력 (24-3 바이너리 입출력) — 실습과제

## 파일 목록

| 파일 | 내용 |
|---|---|
| `a.txt` | 입력용 텍스트 파일 (8자리 정수 10개, 한 줄에 하나, 마지막 줄도 줄바꿈, CRLF → 100바이트) |
| `실습과제1.c` | a.txt의 정수 10개를 읽어 바이너리 파일 b.bin으로 출력하고 16진수로 확인 |
| `실습과제2.c` | b.bin에서 정수 10개를 읽어 화면에 출력 (a.txt와 비교) |
| `실습과제3.c` | a.txt, b.bin의 파일 크기를 바이트 단위로 계산해 출력 |

실행 순서: `실습과제1` → `실습과제2` → `실습과제3` (b.bin은 실습과제1이 만든다)

## 핵심 개념

- **텍스트 저장 vs 바이너리 저장**: `10000000`을 텍스트로 저장하면 글자 8개 = 8바이트(+줄바꿈), 바이너리(int)로 저장하면 항상 4바이트이다.
- `fwrite(buf, sizeof(int), 10, fp)` : int 10개를 변환 없이 메모리 그대로 저장 → 4 × 10 = **40바이트**
- `fread(buf, sizeof(int), 10, fp)` : 파일에서 int 10개를 buf로 읽음. 반환값이 count보다 작으면 오류 또는 파일 끝.
- 리틀 엔디안이라 낮은 자리 바이트가 먼저 저장된다. 예) `10000000` = 0x00989680 → 파일에는 `80 96 98 00` 순서.

## 실습과제3 파일 크기 계산

- a.txt: 숫자 8글자 + 줄바꿈 `\r\n` 2바이트 = 10바이트 × 10줄 = **100바이트**
  (윈도우 텍스트 모드는 `\n`을 `\r\n`으로 저장하므로 2바이트. 바이너리 모드로 열어야 `\r\n`이 그대로 2바이트로 읽혀 실제 크기와 같다.)
- b.bin: 4바이트 × 10개 = **40바이트**
