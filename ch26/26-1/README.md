## 실습과제1

### 1. 프로그램 개발 과정 (편집 → 선행처리 → 컴파일 → 링크 → 실행)

| 단계 | 설명 | 사용 프로그램 | 결과 파일 |
|---|---|---|---|
| 편집(Edit) | C언어로 소스코드를 작성한다. | 에디터(Editor) | 소스파일 `*.c` |
| 선행처리(Preprocess) | 컴파일 전에 `#`으로 시작하는 명령문을 처리한다. `#include`로 헤더파일 내용을 소스에 삽입하고, `#define`으로 정의한 매크로를 몸체로 치환한다. 결과도 C언어 소스이다. | 선행처리기(preprocessor) | 수정된 소스(C언어) |
| 컴파일(Compile) | 선행처리가 끝난 C 소스를 기계어(이진수)로 번역한다. | 컴파일러(compiler) | 목적파일 `*.obj` |
| 링크(Link) | 목적파일들과 라이브러리 목적파일(`printf`, `scanf` 등의 정의)을 연결해 하나의 실행파일로 만든다. | 링커(linker) | 실행파일 `*.exe` |
| 실행(Execute) | 보조기억장치의 실행파일을 주기억장치(RAM)에 올려(load) CPU가 명령어를 수행한다. | 로더(loader) | - |
| 디버깅(Debugging) | 각 단계에서 나온 오류(컴파일 오류, 링크 오류, 실행 오류)를 소스에서 수정하고 다시 컴파일 → 링크 → 실행을 반복한다. | 디버거(debugger) | - |

선행처리 → 컴파일 → 링크를 묶어 **빌드(Build)** 라고 하며, 에디터·컴파일러·링커·디버거를 합쳐 둔 것이 통합개발환경(IDE, 예: Visual Studio)이다.

### 2. 소스파일(.c), 목적파일(.obj), 실행파일(.exe) 위치 확인 (캡쳐)

> ⚠️ 이 부분은 내 컴퓨터에서 직접 해야 하는 작업이라 캡쳐는 포함하지 못했다. 아래 순서대로 캡쳐해서 제출 문서에 첨부하면 된다.

1. Visual Studio에서 간단한 예제 프로젝트(예: `printf("Hello")`)를 만들고 **빌드(Ctrl+Shift+B)** 한다.
2. 파일탐색기 → **보기 → 표시 → 파일 확장명** 을 체크해서 확장자가 보이게 한다.
3. 위치와 예상 파일은 다음과 같다. (Visual Studio 기본 설정 기준, 프로젝트 이름이 `Project1`일 때)

| 파일 | 일반적인 위치 |
|---|---|
| 소스파일 `Source.c` | `솔루션폴더\Project1\Source.c` (프로젝트 디렉터리) |
| 목적파일 `Source.obj` | `솔루션폴더\Project1\x64\Debug\Source.obj` 또는 `Debug\Source.obj` |
| 실행파일 `Project1.exe` | `솔루션폴더\x64\Debug\Project1.exe` 또는 `솔루션폴더\Debug\Project1.exe` |

4. 세 파일이 한 화면에 보이도록 탐색기 검색창에 `Source.c`, `*.obj`, `*.exe`로 검색하거나 폴더를 각각 캡쳐한다. (솔루션 탐색기에서 프로젝트 우클릭 → "파일 탐색기에서 폴더 열기"가 편하다.)

## 실습과제2

> 모든 함수를 사용할 때 반드시 선언, 호출, 정의가 모두 포함되어야 한다.

| 구분 | `printf`, `scanf` 같은 표준 라이브러리 함수에서 어디에 있는가 |
|---|---|
| **선언** | **헤더파일**(`stdio.h`)에 있다. `#include <stdio.h>`를 쓰면 선행처리기가 `stdio.h`의 내용을 소스에 그대로 삽입하므로, 선행처리 후 소스 앞부분에 `int __CRTDECL printf(char const* const _Format, ...);` 같은 선언이 들어온다. 그래서 라이브러리 함수를 호출하기 전에 반드시 헤더파일을 포함해야 한다. 헤더파일은 컴파일러에 설정된 디렉터리(`<파일이름>`)에 있다. |
| **호출** | **내가 작성한 소스파일의 `main` 함수 안**에 있다. (`printf("...");`, `scanf("%d", &a);`) |
| **정의** | **라이브러리 파일**에 있다. 함수의 실제 구현 코드는 미리 컴파일된 **목적파일(`.obj`) 형태의 라이브러리**(예: `libc.obj`)로 존재하고, 링크 단계에서 링커가 내 `main.obj`와 연결해 `main.exe`를 만든다. |

정리하면 선언은 헤더파일(`stdio.h`)에서 컴파일러가 호출 형식을 검사할 때 쓰이고, 정의는 라이브러리 목적파일에서 링커가 찾아 연결한다. 헤더만 포함하고 라이브러리가 없으면 링크 오류가 발생한다.

## 실습과제3 (설명)

### 1. 매크로 상수를 사용하는 이유

- **가독성 증가**: `3.14159`, `10` 같은 숫자 대신 `PI`, `UP`처럼 의미 있는 이름을 쓰면 코드를 읽는 사람이 의도를 바로 알 수 있다.
- **유지보수 용이**: 같은 값이 여러 곳에 쓰일 때 `#define` 한 줄만 고치면 모든 곳에 반영된다. (예: 학생 수 `MAX_STUDENT`를 3에서 30으로 바꿀 때)
- **오타·실수 방지**: 긴 상수나 문자열을 매번 입력하지 않아도 된다.
- 매크로 상수는 선행처리 단계에서 몸체로 **단순 치환**되므로 변수와 달리 실행 시 메모리를 쓰지 않는다.

### 2. 예제 소스코드 설명 (`실습과제3.c`)

| 코드 | 설명 |
|---|---|
| `#define PI 3.14159` | 원주율을 매크로 상수로 정의. 선행처리 때 `PI`가 `3.14159`로 치환된다. 세미콜론은 붙이지 않는다. |
| `#define MAX_STUDENT 3` | 배열 크기(`score[MAX_STUDENT]`), 반복 횟수(`i < MAX_STUDENT`), 평균 계산에 같은 값을 쓴다. 숫자를 바꾸려면 이 한 줄만 고치면 된다. |
| `#define SCHOOL "한국대학교"` | 문자열도 매크로 상수로 정의 가능하다. `printf("학교: %s\n", SCHOOL)`은 선행처리 후 `printf("학교: %s\n", "한국대학교")`가 된다. |
| `#define LINE puts("----...")` | 문장도 매크로 몸체로 정의할 수 있다. `LINE;`은 `puts("--------------------");`로 치환된다. |
| `2 * PI * radius`, `PI * radius * radius` | 반지름을 입력받아 원 둘레와 면적을 구한다. |
| `for (i = 0; i < MAX_STUDENT; i++)` | 점수를 입력받아 `sum`에 누적하고, `(double)sum / MAX_STUDENT`로 평균을 구한다. 정수 나눗셈이 되지 않도록 `double`로 형변환한다. |

실행 예 (반지름 2, 점수 80/90/100 입력):

```
학교: 한국대학교
--------------------
원의 반지름을 입력하세요 : 2
원 둘레: 12.57
원 면적: 12.57
--------------------
1번 학생 점수 : 80
2번 학생 점수 : 90
3번 학생 점수 : 100
평균: 90.00
```

## 실습과제4 (설명)

원래 코드는 `case 10:`, `case 20:` 같은 숫자만 보여서 각 숫자가 무슨 방향인지 알 수 없다. `UP`, `DOWN`, `LEFT`, `RIGHT` 매크로 상수를 정의해 `case UP:`처럼 쓰면 코드만 읽어도 의미를 알 수 있고, 값을 바꿀 때도 `#define`만 수정하면 된다. 실행 결과는 `현재방향: 위`.
